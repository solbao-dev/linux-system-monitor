# 🚀 리눅스 시스템 관제 자동화 스크립트 개발 (b1-1 과제)

본 프로젝트는 다중 사용자 환경에서의 권한 관리, 네트워크 보안 설정(SSH/방화벽), 그리고 시스템 리소스 관제 및 로그 관리를 자동화하는 쉘 스크립트(Bash) 개발을 포함합니다.

---

## 🛠️ 0. 환경 구성 트러블슈팅 보고서

### 📌 배경
Ubuntu 서버 실습을 위해 Mac 환경에서 Linux VM 환경을 구성해야 했다. 관리자 권한 없이, 실제 서버와 최대한 동일한 환경을 만드는 것이 목표였다.

### 🔍 시도 1. 가상화 도구 선택 - OrbStack vs UTM 비교

#### [후보 검토]
| 항목 | OrbStack | UTM |
| :--- | :--- | :--- |
| **설치 방식** | Homebrew로 간편 설치 | DMG 직접 설치 가능 |
| **가상화 방식** | 컨테이너 기반 (Docker 유사) | 완전한 VM (QEMU 기반) |
| **실제 서버와의 유사도** | 낮음 (커널 공유) | ✅ 높음 (독립 커널) |
| **네트워크 설정** | 제한적 | ✅ 실제 서버와 동일하게 설정 가능 |
| **SSH 설정** | 자동 처리됨 | ✅ 직접 설정 필요 (실습 적합) |
| **방화벽(UFW)** | 제한적 | ✅ 완전히 동작 |
| **성능** | 가벼움 | 상대적으로 무거움 |
| **과제 적합도** | ⚠️ 부분적 | ✅ **완전히 적합** |

#### [핵심 차이점 상세 설명]
- **OrbStack의 한계:** 컨테이너 방식이라 Mac의 커널을 공유함. SSH, 방화벽, 계정 권한 등을 실제 서버처럼 완전히 독립적으로 설정하기 어려워 "실제 서버 환경 구성"이라는 과제 목표와 맞지 않음.

- **UTM을 선택한 이유:** QEMU 기반 완전한 가상화로 실제 서버와 동일한 환경을 제공함. UFW 방화벽, SSH 포트 변경, 계정/권한 관리 모두 실제처럼 동작하며, Ubuntu Server ISO를 직접 설치하므로 실제 서버 배포와 동일한 경험을 쌓을 수 있음.
- **결정:** ✅ **UTM 선택** (실제 서버 환경과 100% 동일한 환경 구성 가능)

### ❌ 시도 2. Homebrew를 이용한 UTM 설치 실패 (권한 에러)
- **문제 발생:** 교육장 공용 PC 환경에서 `brew install --cask utm` 실행 시 `/usr/local/Cellar` 등 주요 디렉토리의 쓰기 권한 부족(`not writable`) 에러 발생.

- **원인 분석:** 기존 설치된 Homebrew 폴더의 소유권이 현재 로그인한 사용자 계정과 달라 발생한 권한 충돌. 공용 PC 특성상 `sudo chown` 조치를 위한 관리자 패스워드 획득이 불가능함.
- **해결 방안 (우회 경로):** 홈브루를 통한 설치를 철회하고, **UTM 공식 웹사이트에서 직접 `.dmg` 파일을 다운로드**하여 유저 로컬 애플리케이션 경로(`~/Applications/`)에 마운트 및 복사하는 방식으로 관리자 권한(sudo) 없이 설치 성공.

```bash
# 유저 로컬 어플리케이션 폴더 생성 및 마운트 후 복사 우회

mkdir -p ~/Applications && hdiutil attach ~/Downloads/UTM.dmg

cp -R /Volumes/UTM/UTM.app ~/Applications/

hdiutil detach /Volumes/UTM && open ~/Applications/UTM.app
```
